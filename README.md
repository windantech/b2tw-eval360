# B2THEWORLD · Eval360

A demonstration of **Eval360** configured around B2THEWORLD's own work: transformative education
for children affected by war, across Rwanda, South Sudan, Cameroon, Pakistan and Iraq, delivered
through a partnership-based member school model.

**→ [mel.eval360.tech/b2tw](https://mel.eval360.tech/b2tw/)**

---

## What this is for

B2THEWORLD does not lack an M&E plan. It has **three documents that disagree in nine places**,
**eleven sections that were never filled in**, and a **newer theory of change with no targets
attached to it**.

A reporting system that quietly picks one of those numbers is worse than no system, because the
figure it picks becomes the denominator of every percentage anyone ever reports. So this one:

1. **Holds all three documents, separately.** The 2024 logframe runs the operational screens
   because it is the only one with targets. POOA v5 is the adopted theory of change and has its
   own screen. They are never merged.
2. **Shows every difference, quoted from both sides, and records what a person decides** — with a
   name and a date, changeable on one screen, carried through every dependent figure. The code
   never chooses.
3. **Names what is missing instead of reporting zero.** A blank section of the plan prints what is
   missing, where it is missing from, and the question that would fill it.

## Building

```bash
node scripts/build-guide.js
```

Nothing else to build. The system is one HTML file with no dependencies beyond Chart.js and
Bootstrap Icons from a CDN — no framework, no bundler, no server.

## How it is put together

- **`appData` is the only source of truth.** No figure is written into HTML. If it appears on
  screen it came from `appData` or a calculator over it, read at the moment it is shown.
- **Deterministic.** A fixed seed, so the figures are identical on every machine, every time.
- **No browser storage.** State lives in memory for the session, and the system says so where
  somebody might assume otherwise.
- **The guide is generated, not written.** Every figure in it is a real screen rendered with the
  project's own records. There is not a screenshot anywhere in it, so it cannot describe a version
  of the system that no longer exists.

## Safeguarding

These are children in conflict zones.

- No child is named anywhere in the system.
- Student data is aggregate by default; every figure is a count.
- No account, at any level, can open an individual record — none exists.
- None of the six generated reports carries individual data, and the donor update's photo section
  is deliberately empty with the reason printed in it.

## A note on the figures

They are **illustrative** — shaped like B2THEWORLD's work, not its actual records. They are there
so the system can be seen working. The structure, the targets, the contradictions and the gaps are
all real, taken from the source documents.
